# 2026-08-29 GitHub Pages 历史数据按需加载优化

### 编写人

dumpling

### 请求

将远程历史走势页面从单日大 JSON 升级为按日期索引和主播分片的 schema v2，在不改变用户操作逻辑和原始采样语义的前提下降低首屏传输、解析和 SVG 绘制成本。

### 影响模块

- `src/historySiteExport.ts`：v2 导出契约、活跃/闲置分类、内容版本和原子写入。
- `site/app.js`：日期索引、按需加载、并发队列、缓存、取消、重试、范围缓存和降采样。
- `scripts/migrate-history-site-v2.mjs`、`scripts/validate-history-site.mjs`：一次性无损迁移及 v2 完整性校验。
- `site/data/v2/`：真实历史数据迁移；删除已替代的 v1 工作树数据。
- 历史页面测试、根 README、产品概览、架构、模块索引和本模块 PRD。

### 代码变更

- 导出根目录切换为 `site/data/v2/`；每个日期生成索引，当天存在正数采样的主播使用独立文件，其余主播合并进入 `idle.json`。
- 每个日期、主播、闲置和场次文件引用携带 SHA-256 内容版本、字节数和采样点数；不变文件不重写，Manifest 原子最后更新。
- `.gitattributes` 强制 `site/data/**/*.json` 使用 LF，避免 Windows 自动换行转换破坏内容哈希或重复导出稳定性。
- 页面默认筛选改为“有数据”，v1 localStorage 状态升级时保留日期、范围、场次、合计、图例、主题和高度，但使用新的默认筛选。
- 日期索引并行读取；必需主播文件最多 8 路并发，失败自动重试一次，过期请求取消，已解析文件按内容版本缓存。
- 只有切换全部、分组、合计或重新显示对应图例时才补载额外数据；场次定位只请求实际可见主播。
- 时间范围用二分查找截取并缓存；合计、纵轴、峰值和悬浮使用原始点，SVG 路径按像素桶保留首尾、峰谷和断线边界。
- 真实数据从 v1 无损迁移为 v2：62 个房间、17 个日期、4,693,894 个采样点，v2 文件总计约 62.2 MB。

### PRD 更新

- 更新 `docs/prd/modules/history-site.md`、`docs/prd/architecture.md`、`docs/prd/product-overview.md`、模块索引、PRD 首页和根 README。

### 验证

- v1→v2 迁移逐日逐房间深度比较通过。
- v2 数据校验通过：62 个房间、17 个日期、4,693,894 个采样点。
- `npm.cmd test`：通过，TypeScript 编译及 151 项测试全部成功。
- 本地桌面浏览器首屏约 271 ms：40 个数据请求（Manifest、1 个日期索引、38 个活跃主播文件），未请求 `idle.json`，最大并发 8。上一版 v1 最新单日文件为 3,851,418 字节，v2 默认首屏原始传输约 1,408,619 字节，减少约 63.4%。
- 首屏 196,194 个原始采样继续用于计算和悬浮，1440 像素桌面视口实际绘制 49,322 个 SVG 点；双日午夜线、全部范围增量加载和场次单主播定位通过。
- 390×844 移动视口绘制 38 条曲线，页面宽度与视口同为 390 像素，无横向溢出；桌面与移动控制台均无错误，截图保存在本地 `.temp/`。
- GitHub Pages 工作流成功后两次线上复测通过：默认首屏压缩传输约 0.92 至 0.94 MB、首图约 3.95 至 4.47 秒，最后一个数据响应完成后约 85 ms 完成解析、计算和首图绘制；全部范围、双日和场次定位继续通过。
- `node --check`、PRD Keeper、数据校验和 VSIX 打包通过；VSIX 为 73 个文件、182.1 KB。

### 风险/后续事项

- 原始 15 秒采样仍会使仓库总量持续增长；本次优化主要减少浏览器按次传输、解析和绘制量，不消除长期存储增长。
- `idle.json` 在用户选择“全部”或包含闲置主播的范围时仍可能较大，但默认首屏不会请求。

# 远程场次峰值图同步 VS Code 交互优化

### 编写人

dumpling

### 请求

把 VS Code 历史走势中已完成的场次峰值图高度、纵轴刻度和悬浮详情调整同步到 GitHub Pages 网页端，并完成远程发布。

### 影响模块

- `site/index.html`、`site/app.js`、`site/styles.css`：场次峰值高度控件、持久化、动态 SVG 高度、纵轴刻度和浮层定位。
- `src/test/historySiteRuntime.test.ts`：网页端与 VS Code 行为一致性回归约束。
- `docs/prd/modules/history-site.md`：同步远程页面当前交互规则。

### 代码变更

- 在历史控制区最顶部增加场次峰值图高度滑杆，默认 180px，限制为 160–640px，并通过 localStorage 持久化。
- 图表、加载、错误和空状态均使用所选高度；纵轴按高度生成 4–10 个目标区间的易读整数刻度与网格线。
- 悬浮详情测量自身尺寸后优先显示于点位上方，空间不足时翻到下方，并限制在图表左右边界内。

### PRD 更新

- 更新 `docs/prd/modules/history-site.md`，移除固定 180px 的旧描述，补充高度、刻度和悬浮边界规则。

### 验证

- `node --check site/app.js` 与 `git diff --check` 通过。
- `npm.cmd test` 通过：TypeScript 编译成功，151 项 Node 测试全部通过。
- `npm.cmd run validate:history-site` 通过：62 个房间、18 个日期、4,736,815 个采样点。
- PRD Keeper 校验通过。
- Playwright 桌面验收通过：高度从 180px 调整到 640px 后纵轴网格线由 4 条增加至 7 条，页面刷新后高度仍为 640px，悬浮详情保持在图表边界内。
- Playwright 390×844 移动视口验收通过：高度 320px 生效，页面无横向溢出，悬浮详情保持在图表边界内。

### 风险/后续事项

- 本次只调整静态页面交互和浏览器本地状态，不改变 v2 导出数据格式、插件本地历史格式或 Pages 部署流程。
