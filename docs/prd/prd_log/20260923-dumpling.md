# 2026-09-23 BWatch 性能与持久化可靠性落地

### 编写人

dumpling

### 请求

落实 BWatch 性能优化方案：持续采集不受视图隐藏和写盘阻塞影响，历史数据可靠持久化并在正常停用时 flush，同时减少弹幕消息和 B站字段请求的无效开销。

### 影响模块

- src/liveMonitor.ts：完成后调度、配置 revision、迟到结果丢弃、后台历史写入。
- src/onlineHistoryStore.ts：每房间 WAL、sequence、校验恢复、sync、flush、状态和迁移标记。
- src/webviewProvider.ts、src/danmakuWebviewProvider.ts：可见性门控、监听器清理、消息错误隔离和最新快照恢复。
- src/danmakuStatusBar.ts、src/danmakuProtocol.ts：状态栏节流、坏包恢复扫描预算。
- src/bilibiliClient.ts：字段缓存 LRU、房间/UID 生命周期清理与 in-flight 请求合并。
- src/extension.ts、src/types.ts：停用 flush 和 snapshot revision。
- src/test/onlineHistoryStore.test.ts：WAL 重复、乱序、半写尾部恢复、异步入队、待写年龄和 flush 状态测试。

### 代码变更

- 自动刷新从固定 setInterval 改为上一轮完成后安排下一轮，同一房间不会因刷新重叠产生迟到覆盖。
- 在线历史先合并入内存并异步入队，再按房间批量追加带校验的 WAL；批量追加后 FileHandle.sync，失败队列保留并重试，正常停用由扩展 deactivate 等待 flush。
- 启动恢复兼容旧 JSON 和 globalState，迁移标记只写一次；WAL 解析按 sequence 去重并忽略损坏尾部。
- 隐藏监控/弹幕 Webview 停止普通消息投递，恢复可见后发送完整快照；retainContextWhenHidden 关闭以释放隐藏页面内存。
- B站 fans/guard/online 缓存增加 LRU 和同 key in-flight Promise 合并；弹幕状态栏高频消息节流，协议恢复扫描设有预算。

### 风险/后续事项

- 健康磁盘下最多约 5 秒未 sync 数据可能在进程崩溃或断电时丢失；磁盘损坏、写满和强制终止无法承诺绝对零丢失。
- 当前查询仍基于扩展进程内的长期历史投影；按日期分段索引和完整 profiling 属于后续阶段。
- record() 不等待磁盘；健康运行由约 1 秒批量 flush 驱动，正常停用必须调用并等待 flush()，异常终止最多损失尚未 sync 的短窗口数据。
