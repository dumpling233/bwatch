# 2026-09-24 BWatch 监控快照增量协议

### 编写人

dumpling

### 请求

继续落地 BWatch 性能优化方案，减少监控 Webview 全量快照消息带来的 Extension Host 与 Webview 之间的消息体和重复序列化开销，同时保持持续采集、历史持久化和弹幕连接稳定。

### 影响模块

- `src/types.ts`：新增 `MonitorHistoryPatch`、`MonitorSnapshotPatch` 和 `MonitorSnapshotEnvelope` 类型。
- `src/webviewProvider.ts`：按 revision 连续性发送 full/patch 快照；隐藏恢复、ready、投递失败时回退 full。
- `media/webview.js`：接收并合并 patch，检查 `baseRevision`，失配时重新握手；兼容旧版无 mode 的 full 消息。
- `src/test/webviewRuntime.test.ts`：增加历史 append/replace/remove 和 revision 缺口回退测试。
- `media/webview.js`：趋势 SVG 连续数据段按像素宽度做 min/max 桶下采样，保留端点、极值和断线边界。
- `media/webview.js`：房间列表增加布局签名和 `data-room-id` 节点复用；快照刷新仅更新房间动态字段、分组聚合数字和趋势图，不重建稳定 DOM 结构。

### 代码变更

- 宿主侧保存最近一次成功投递快照，仅在可见且 revision 连续时生成 patch。
- 房间历史点在公共前缀未变化时传新增点；重排、修正或其他非前缀变化传完整房间序列；删除房间传 `removeRoomIds`。
- Webview patch 合并采用拷贝后的房间历史，不修改旧快照；`message: null` 删除旧消息字段，旧 revision 或缺少基线时发送 `ready` 请求完整状态。
- `postMessage` 使用 `Promise.resolve` 兼容 VS Code `Thenable`，投递失败清除 patch 基线，避免后续 patch 建立在未知状态上。
- 下采样只作用于 SVG path 生成；完整历史数组仍参与坐标缩放、图例和悬浮计算，采集和持久化数据不裁剪。
- 局部 DOM 更新只读取当前快照并复用事件节点；布局变化仍走完整重建，保证模式、排序、分组和编辑器状态切换的原有行为。

### PRD 更新

已更新 `docs/prd/modules/live-monitor.md`、`docs/prd/architecture.md` 和 `docs/prd/README.md`，记录增量快照边界及 full 回退规则。弹幕连接、消息队列、历史 WAL 和采集调度没有改变；弹幕模块仍保持原有可见性契约。

- 增加监控快照 patch 合并回归测试，覆盖 `append`、`replace`、`removeRoomIds`、message 删除和 revision 缺口握手。
- 增加趋势下采样回归测试，覆盖端点、极值和 `null` 断线边界。
- 增加房间列表局部渲染回归测试，覆盖布局签名、稳定房间节点和分组动态指标更新。

## 本轮追加：采集请求隔离与 WAL 恢复加固

### 编写人

dumpling

### 需求与影响模块

继续完成性能优化方案，保证单房间慢请求不会拖住其他房间，并提高异常退出/磁盘异常后的历史恢复可观察性。影响 `src/bilibiliClient.ts`、`src/onlineHistoryStore.ts`、对应单元测试及直播监控/架构 PRD。

### 代码变更

- `BilibiliLiveClient` 对基础信息、在线、舰队、粉丝和搜索请求统一增加 AbortSignal 与本地超时边界；支持可选 `onRequest` 指标回调，指标不包含响应正文且回调异常不会影响采集。
- 房间级补充请求增加异常隔离；基础信息批量请求失败时沿用最近成功响应但显式写入房间错误，失败请求不更新成功缓存时间，后续刷新继续重试。
- 基础信息降级优先复用最近一次完整房间投影，保留上一轮在线、舰队和粉丝字段，再更新 `lastUpdatedAt` 并附加错误说明；房间移除或 UID 变化时清理该投影缓存。
- WAL 启动恢复在最后一个无效/半写记录处执行尾部截断；旧 globalState 迁移 checkpoint 写入失败进入 degraded 状态，不阻止扩展继续启动和采集。
- 新增单房间超时隔离、基础信息降级和请求指标回归测试，并验证损坏尾部修复。

### PRD 与验证

- 更新 `docs/prd/modules/live-monitor.md` 与 `docs/prd/architecture.md`，同步请求超时、旧值降级、WAL 尾部恢复和指标边界。
- `npm.cmd test`：161 项测试全部通过，包含 TypeScript 编译。

### 风险/后续事项

- 当前仍未在真实 10 房间长时间运行中采集 CPU/RSS 基线；`onRequest` 只提供可插拔指标回调，尚未新增默认输出或性能面板。
- 长期历史按日期分段惰性读取和真实磁盘 ENOSPC/权限故障注入仍需后续专项测试。
