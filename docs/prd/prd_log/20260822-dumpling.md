# 单主播直播场次历史分析

### 编写人

dumpling

### 请求

在历史走势控制面板增加单主播直播场次级联筛选，基于本地长期在线人数数据识别每一场直播；点击场次后快速定位历史走势图，同时保留原有日期、时间、范围、图例和合计控制能力。

### 影响模块

- src/types.ts：新增 LiveSessionSummary 场次摘要数据结构。
- src/onlineHistoryStore.ts：新增按房间扫描全部本地长期历史的场次识别逻辑。
- src/webviewProvider.ts、src/extension.ts：保留场次加载消息和宿主回调，移除独立主播历史分析子面板容器。
- media/webview.js、media/webview.css：新增历史走势顶部级联控件、状态持久化、图例初始隐藏和历史走势联动。
- 场次识别单元测试和 Webview 运行时回归测试。

### 代码变更

- 在线人数大于 0 的连续采样区间视为一场直播；0 结束场次；null 表示采集失败或断线，不强制切断场次。
- null 采样保留在场次中并计入 sampleCount，但不计入 validSampleCount；场次摘要包含起止时间、时长、峰值和采样数量。
- 场次按结束时间从新到旧返回，数据来自全部本地长期历史，不因监控房间删除而清理。
- 主播分析房间和选中场次通过 Webview getState/setState 保存；选择场次前的图例隐藏状态也会保存，清除筛选后恢复。
- 点击场次自动扩展开始前和结束后各 5 分钟；跨午夜复用双日历史查询，时间范围最多两个自然日；用户仍可手动调整历史图。
- 宿主回传主播名称、房间号和场次摘要；读取失败显示在第二级控件并支持重试，不影响实时列表、历史范围筛选和聚合走势。

- 已记录 0 与 null 的不同含义、全部长期历史来源、前后 5 分钟扩展、跨午夜双日规则以及不新增 B站接口的边界。

### 风险/后续事项

- 场次切分依赖定时采样；如果直播期间完全没有采样，无法凭空推断下播时间。
- null 不切断场次可能把长时间网络故障期间的正数样本归入同一场，属于当前采样数据语义下的保守选择。
- B站接口和本地历史采样仍可能存在字段缺失或采样间隔不均，场次摘要应作为辅助分析而不是官方直播记录。
