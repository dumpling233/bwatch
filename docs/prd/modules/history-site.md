# 远程历史走势页面

## 模块定位

远程历史走势页面把 VSCode 扩展本地长期在线人数历史导出为版本化静态数据，并由 GitHub Pages 提供只读查看。模块不提供后端、实时同步或远程写入；用户主动执行插件命令后，自行检查、提交并推送 `site/data/` 变更。

## 用户流程

```text
插件持续采集本地历史
    ↓
运行“BWatch: 导出历史网页数据”
    ↓
检查 site/data/v2 变更
    ↓
手动 git add / commit / push
    ↓
默认分支触发 GitHub Actions 发布 site/
```

首次导出时用户选择包含 `package.json` 和 `site/index.html` 的 `bwatch` 仓库根目录。扩展把绝对路径仅保存到本机 `globalState`；路径失效时重新选择，路径不会写入 VSCode 可同步设置或导出文件。导出命令不执行任何 Git 命令。

## 导出数据契约

网页只接受 `schemaVersion: 2`。数据根目录为 `site/data/v2/`；v1 仅由一次性迁移脚本读取，不再发布到 Pages。

| 文件 | 责任 |
|---|---|
| `manifest.json` | 导出版本、导出时间、IANA 时区、房间稳定顺序、主播名、当前监控状态、分组、日期索引引用和场次文件引用 |
| `dates/YYYY-MM-DD/index.json` | 当天起止时间、活跃房间独立文件引用、闲置房间号和闲置合并文件引用 |
| `dates/YYYY-MM-DD/active/{roomId}.json` | 当天至少出现一个正数采样的房间完整全天原始采样 |
| `dates/YYYY-MM-DD/idle.json` | 当天没有正数采样的房间完整原始采样集合 |
| `sessions/{roomId}.json` | 与 `OnlineHistoryStore.getRoomSessions()` 完全一致的场次摘要 |

导出范围包含全部长期历史，包括已从监控列表移除但仍有本地历史的房间。主播名按历史元数据、当前快照、房间号依次兜底。采样时间戳不取整、不降采样；`null` 继续表示该轮采集失败或断线。

每个文件引用包含相对路径、SHA-256 内容版本、字节数和采样点数。导出按日期和房间稳定排序；日期索引、房间分片、闲置合并文件、场次和 Manifest 都先写临时文件再原子替换，内容未变化的文件不重写，`manifest.json` 最后更新。导出完成后只报告房间数、日期数、采样点数、数据体积和变更文件数。

## 页面能力

- 默认打开最近一个有数据日期；日期输入和可用日期快捷按钮共同切换日期，连续点击相邻日期可加载双日，并在第二天 00:00 绘制午夜分界线。
- 双端分钟范围控件覆盖连续 24/48 小时；跨日标签和所有日期格式化使用 Manifest 导出时区。
- 主播和场次级联选择；选择场次会把普通房间筛选设置为“全部”、把时间定位到场次前后各 5 分钟，并通过普通图例隐藏状态只显示所选主播。合计选择保持不变，但合计曲线在本次定位时隐藏；之后用户可继续操作筛选、时间和图例，清除按钮只清除上方主播/场次选择，不回滚下方状态。
- “全部”“有数据”和自定义分组的房间筛选与 `Σ` 合计曲线分别控制，筛选不会隐式创建合计曲线；新浏览器及从 v1 状态升级的浏览器默认显示“有数据”房间且不启用合计。
- 合计规则与插件一致：缺少同时间戳采样按 0，显式 `null` 使该时间戳合计断线，没有任何数值时为 `null`。
- 房间曲线按 Manifest 稳定房间顺序使用与 VSCode 插件一致的 24 色调色板，超出调色板后使用相同的确定性 HSL 回退；图例位于图表下方并按所选时间范围内最后一个有效在线人数降序排列，支持单条显隐、隐藏全部和全部显示。
- 纵轴按当前时间范围内实际可见的有效数值动态计算上下界和易读刻度；网页中的在线人数、采样量、纵轴刻度和峰值等数值均显示带千位分隔符的完整数字，不使用“千”“万”等缩写；只有一条有效曲线时，在峰值处绘制带数值标签的水平虚线。
- 图表高度通过 160 至 640 像素滑杆调整；SVG 根据容器尺寸重算坐标、刻度、网格和折线。范围截取使用二分查找，合计、纵轴、峰值和悬浮使用完整原始采样，折线绘制按像素桶保留首尾、峰谷和断线边界后降采样。
- 页面默认跟随浏览器系统主题，并可在页头手动切换日间/夜间模式。
- 日期、双日状态、分钟范围、主播、场次、筛选范围、合计范围、图例隐藏集合、历史图高度、场次峰值图高度、场次峰值时段着色开关和手动主题写入浏览器 `localStorage`。
- 历史控制区最顶部提供场次峰值图高度滑杆，位于主播/直播场次级联控件之前；默认 180 像素，可在 160 至 640 像素范围调整。选择主播后显示“场次峰值”分析区，默认展示最近 30 场，可切换最近 10 场、最近 30 场和全部；图表保持 360 像素最小宽度，加载、空数据和错误状态使用当前所选高度。
- 峰值图按场次起始时间排序，纵轴固定从 0 开始，并根据绘图区高度生成 4 至 10 个目标区间的易读整数刻度和网格线；点位悬浮显示完整起止时间、峰值在线人数、直播时长和时段分类，浮层测量自身尺寸后优先显示在点位上方、空间不足时翻到下方，并限制在图表边界内。点击或键盘确认点位会复用场次定位逻辑，下拉选择与点位高亮同步。
- 场次峰值图提供默认关闭的“时段着色”开关。短于 4 小时的场次按其与八个时段的最长重叠分类，跨午夜按自然日累计，并列时使用直播中点且边界归入后一时段；4 小时及以上归为灰色“长场次”。网页始终使用 Manifest 导出时区计算分类，避免访问者浏览器时区改变结果。开启后仅数据点按分类着色，折线保持蓝色，选中点通过加粗外圈表达，图下按 `00:00–24:00` 顺序显示八个时段及长场次图例。
- 场次峰值范围、高度和时段着色选择写入 localStorage，不新增后端接口或数据格式；网页继续使用 Manifest 导出时区和完整数字格式化。
- 页面明确最近状态只是导出快照。Manifest 禁止缓存；其余文件以自身 SHA-256 内容版本作为查询参数，单次导出不会使所有历史文件缓存失效。
- 页面先并行读取 1 至 2 个日期索引，再根据筛选、合计和图例显隐确定必需房间；房间分片最多 8 路并发，文件失败自动重试一次，筛选变化会取消过期请求，已加载内容按文件版本复用。必需文件全部成功后统一更新图表，并显示加载进度。
- 默认“有数据”首屏只请求活跃房间文件，不请求 `idle.json`；切换“全部”、选择包含闲置房间的分组、显示隐藏图例或显示对应合计时才补载闲置数据。场次定位即使把筛选设为“全部”，也只加载实际可见的所选主播。

## 异常与安全边界

- Manifest 损坏、版本不兼容、日期索引/房间/闲置/场次文件缺失或网络加载失败时显示可读错误，不继续用不完整数据绘图。
- `scripts/validate-history-site.mjs` 校验所有索引、引用、排序、时间范围、采样值和场次摘要基本结构；Pages 工作流在发布前必须通过校验。
- 导出只包含房间号、主播名、分组、采样时间、在线人数、场次摘要和导出时最近状态，不读取或输出 Cookie、Token、代理配置、弹幕、SC 或其他 VSCode 状态。
- GitHub Pages 为公开站点，仓库中的导出数据可被任何访问者下载；不使用 Git LFS。
- 静态页面只展示最新提交的数据，Git 提交历史不作为网页查询接口。
- 原始 15 秒采样会持续增加仓库和 Pages 体积；按日、按活跃房间分片减少首屏传输和旧文件重复重写，但不能消除仓库长期增长。

## 部署

`.github/workflows/pages.yml` 在仓库默认分支 push 或手动触发时运行数据校验，并使用官方 Pages Actions 发布 `site/`。工作流通过 `github.event.repository.default_branch` 判断默认分支，不硬编码分支名。

仓库首次使用时，在 GitHub `Settings > Pages > Build and deployment > Source` 选择 `GitHub Actions`。当前仓库的预期项目页地址为 `https://dumpling233.github.io/bwatch/`；只有首次推送并且 Pages 工作流成功后，该地址才可访问。

## 验收标准

- 原始毫秒时间戳、数值和 `null` 经导出后可以无损还原。
- 午夜两侧采样进入不同日期文件，已移除房间继续存在，场次摘要与本地存储查询一致。
- 相同输入和固定导出时间重复导出不产生文件变更，Manifest 不残留临时文件。
- v1→v2 迁移逐点验证时间偏移、数值、`null`、排序和日期边界；真实数据迁移结果为 62 个房间、17 个日期、4,693,894 个采样点。
- 默认“有数据”首屏不读取闲置合并文件，并发房间请求不超过 8；过期请求可取消，相同内容版本复用缓存。
- 降采样后的折线保留首尾、峰值、低谷和断线分段，纵轴、合计与悬浮仍基于原始采样。
- 空数据页面、有效数据页面、单日、双日、场次定位、范围合计、图例和移动布局均可用。
- TypeScript 编译、Node 测试、静态脚本语法检查、数据校验、PRD 校验和 VSIX 打包通过。
