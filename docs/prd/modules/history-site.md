# 远程历史走势页面

## 模块定位

远程历史走势页面把 VSCode 扩展本地长期在线人数历史导出为版本化静态数据，并由 GitHub Pages 提供只读查看。模块不提供后端、实时同步或远程写入；用户主动执行插件命令后，自行检查、提交并推送 `site/data/` 变更。

## 用户流程

```text
插件持续采集本地历史
    ↓
运行“BWatch: 导出历史网页数据”
    ↓
检查 site/data/v1 变更
    ↓
手动 git add / commit / push
    ↓
默认分支触发 GitHub Actions 发布 site/
```

首次导出时用户选择包含 `package.json` 和 `site/index.html` 的 `bwatch` 仓库根目录。扩展把绝对路径仅保存到本机 `globalState`；路径失效时重新选择，路径不会写入 VSCode 可同步设置或导出文件。导出命令不执行任何 Git 命令。

## 导出数据契约

网页只接受 `schemaVersion: 1`。数据根目录为 `site/data/v1/`。

| 文件 | 责任 |
|---|---|
| `manifest.json` | 导出版本、导出时间、IANA 时区、房间稳定顺序、主播名、当前监控状态、分组、可用日期和文件索引 |
| `dates/YYYY-MM-DD.json` | 一个本地自然日内所有房间的原始采样；点格式为 `[相对当天起点毫秒, 在线人数或 null]` |
| `sessions/{roomId}.json` | 与 `OnlineHistoryStore.getRoomSessions()` 完全一致的场次摘要 |

导出范围包含全部长期历史，包括已从监控列表移除但仍有本地历史的房间。主播名按历史元数据、当前快照、房间号依次兜底。采样时间戳不取整、不降采样；`null` 继续表示该轮采集失败或断线。

导出按日期和房间稳定排序。日期、场次和 Manifest 都先写临时文件再原子替换；内容未变化的文件不重写，`manifest.json` 最后更新。导出完成后只报告房间数、日期数、采样点数、数据体积和变更文件数。

## 页面能力

- 默认打开最近一个有数据日期；日期输入和可用日期快捷按钮共同切换日期，连续点击相邻日期可加载双日，并在第二天 00:00 绘制午夜分界线。
- 双端分钟范围控件覆盖连续 24/48 小时；跨日标签和所有日期格式化使用 Manifest 导出时区。
- 主播和场次级联选择；选择场次会把普通房间筛选设置为“全部”、把时间定位到场次前后各 5 分钟，并通过普通图例隐藏状态只显示所选主播。合计选择保持不变，但合计曲线在本次定位时隐藏；之后用户可继续操作筛选、时间和图例，清除按钮只清除上方主播/场次选择，不回滚下方状态。
- “全部”“有数据”和自定义分组的房间筛选与 `Σ` 合计曲线分别控制，筛选不会隐式创建合计曲线；新浏览器默认显示“全部”房间且不启用合计。
- 合计规则与插件一致：缺少同时间戳采样按 0，显式 `null` 使该时间戳合计断线，没有任何数值时为 `null`。
- 房间曲线按 Manifest 稳定房间顺序使用与 VSCode 插件一致的 24 色调色板，超出调色板后使用相同的确定性 HSL 回退；图例位于图表下方并按所选时间范围内最后一个有效在线人数降序排列，支持单条显隐、隐藏全部和全部显示。
- 纵轴按当前时间范围内实际可见的有效数值动态计算上下界和易读刻度；网页中的在线人数、采样量、纵轴刻度和峰值等数值均显示带千位分隔符的完整数字，不使用“千”“万”等缩写；只有一条有效曲线时，在峰值处绘制带数值标签的水平虚线。
- 图表高度通过 160 至 640 像素滑杆调整；SVG 根据容器尺寸重算坐标、刻度、网格和折线，悬浮显示导出时区下的时间与在线人数。
- 页面默认跟随浏览器系统主题，并可在页头手动切换日间/夜间模式。
- 日期、双日状态、分钟范围、主播、场次、筛选范围、合计范围、图例隐藏集合、图表高度和手动主题写入浏览器 `localStorage`。
- 选择主播后显示“场次峰值”分析区，默认展示最近 30 场，可切换最近 10 场、最近 30 场和全部；固定 180 像素高度、360 像素最小宽度，空数据、加载和错误状态与插件一致。
- 峰值图按场次起始时间排序，使用自适应在线人数纵轴；点位悬浮显示完整起止时间、峰值在线人数和直播时长，点击或键盘确认点位会复用场次定位逻辑，下拉选择与点位高亮同步。
- 场次峰值范围选择写入 localStorage，不新增后端接口或数据格式；网页继续使用 Manifest 导出时区和完整数字格式化。
- 页面明确最近状态只是导出快照。Manifest 禁止缓存；日期和场次文件使用导出时间版本参数刷新。

## 异常与安全边界

- Manifest 损坏、版本不兼容、日期/场次文件缺失或网络加载失败时显示可读错误，不继续用不完整数据绘图。
- `scripts/validate-history-site.mjs` 校验所有索引、引用、排序、时间范围、采样值和场次摘要基本结构；Pages 工作流在发布前必须通过校验。
- 导出只包含房间号、主播名、分组、采样时间、在线人数、场次摘要和导出时最近状态，不读取或输出 Cookie、Token、代理配置、弹幕、SC 或其他 VSCode 状态。
- GitHub Pages 为公开站点，仓库中的导出数据可被任何访问者下载；不使用 Git LFS。
- 静态页面只展示最新提交的数据，Git 提交历史不作为网页查询接口。
- 原始 15 秒采样会持续增加仓库和 Pages 体积；按日分片仅减少旧日期的重复重写，不能消除长期增长。

## 部署

`.github/workflows/pages.yml` 在仓库默认分支 push 或手动触发时运行数据校验，并使用官方 Pages Actions 发布 `site/`。工作流通过 `github.event.repository.default_branch` 判断默认分支，不硬编码分支名。

仓库首次使用时，在 GitHub `Settings > Pages > Build and deployment > Source` 选择 `GitHub Actions`。当前仓库的预期项目页地址为 `https://dumpling233.github.io/bwatch/`；只有首次推送并且 Pages 工作流成功后，该地址才可访问。

## 验收标准

- 原始毫秒时间戳、数值和 `null` 经导出后可以无损还原。
- 午夜两侧采样进入不同日期文件，已移除房间继续存在，场次摘要与本地存储查询一致。
- 相同输入和固定导出时间重复导出不产生文件变更，Manifest 不残留临时文件。
- 空数据页面、有效数据页面、单日、双日、场次定位、范围合计、图例和移动布局均可用。
- TypeScript 编译、Node 测试、静态脚本语法检查、数据校验、PRD 校验和 VSIX 打包通过。
