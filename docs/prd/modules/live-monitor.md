# 直播监控扩展

## 当前行为

`bwatch` 在 VSCode Activity Bar 中提供 `BWatch` 容器，并在其中展示 `Bilibili Live Monitor` 侧边栏 Webview。用户可以监控多个 B站直播间房间号，查看每个房间的主播/房间名、直播标题、主播粉丝数、开播状态、在线观众人数、已开播时长、舰队总人数、整体刷新状态、单主播最近在线人数走势和主播总览走势；当当前网络环境导致 VSCode/Node 请求 B站接口失败时，扩展支持显式 HTTP/HTTPS 代理配置和命令面板网络诊断。

## 用户交互

- “主播总览”面板标题栏右侧常驻搜索添加直播间和手动刷新图标按钮；新建分组和列表配置入口位于“直播间列表”子面板标题栏右侧。主面板外层使用贴近 VSCode 侧栏的紧凑边距和 4px 圆角，标题栏与内容区保持统一内边距。
- 用户点击搜索添加图标后，扩展打开 VSCode 原生输入框；输入纯数字直播间房间号时通过房间基础信息链路校验并补齐主播名、粉丝数和直播状态，不调用 B站主播搜索接口。
- 用户在 VSCode 原生输入框输入主播名关键词后触发 B站主播模糊搜索，并在 VSCode 原生候选列表中展示候选直播间；房间号直查和主播名搜索统一展示主播名、房间号、分区、粉丝数、直播状态和已监控状态，房间号链路未提供分区时显示“未知分区”。
- 房间号直查返回不存在、未知或错误状态时不生成可添加的正常候选，并通过 VSCode 原生提示展示具体错误。
- 搜索接口失败时通过 VSCode 原生提示显示可恢复错误，并建议用户稍后再试或直接输入直播间房间号。
- 搜索候选会与当前 `bwatch.rooms` 监控列表对比；已在监控列表中的候选显示 `已监控` 状态，选择后不会重复添加。
- 用户在 VSCode 原生候选列表中选择未监控直播间后，房间号写入 `bwatch.rooms`。
- 每个直播间条目支持打开直播间页面、删除房间，以及通过“弹”按钮切换到实时弹幕机并自动连接该直播间；详细模式和简略模式使用同一入口行为。
- “主播总览”面板标题栏右侧提供手动刷新按钮；搜索添加按钮与其并列，两个入口保留原有消息和状态逻辑。
- 每次刷新先用一个批量房间基础信息请求获取全部房间的主播名、直播状态、标题、人气和开播时间；再对有 UID 的房间补充粉丝数、舰队总人数，并仅对开播房间补充直播页在线人数。补充请求按房间限制并发，避免大量房间同时请求造成接口限流或代理拥塞。
- 粉丝数在内存中缓存 5 分钟，舰队总人数缓存 1 分钟；缓存有效期内不重复请求，缓存过期后重新获取。补充接口失败时优先保留上一次成功值，首次获取失败才显示缺失状态；在线人数不使用缓存，以保持每轮刷新实时性。
- 粉丝数或舰队总人数在本轮请求失败但沿用缓存时，列表对应数字显示黄色；鼠标悬浮提示本轮获取失败及最近一次成功获取时间。首次获取失败没有可用缓存时仍显示 `-`。
- 直播间列表子面板作为列表和其操作的统一容器，使用与总览、历史走势一致的标题栏结构，默认显示列表、状态和日常控制；标题栏可整体展开/收起，收起时只隐藏列表内容并保留标题和右侧操作。排序、分组、刷新等低频配置默认收起，添加直播间和新建分组这类输入型管理动作不占用列表内容空间。
- 直接影响主列表日常查看的展示模式、主播状态筛选、单主播小图开关和小图最近时间范围始终显示在列表上方，不受控制面板折叠状态影响。
- 直播间列表子面板展开配置后按功能范围分为“排序”“分组”“刷新”三组；这些配置和主列表的展示模式、状态筛选、小图控制、刷新摘要及分组详情列表属于同一子面板，控件位置调整不改变原有配置、消息和状态逻辑。总览和历史走势继续使用独立面板。
- 常驻的主列表控制区提供展示模式切换和主播状态筛选；默认详细模式保留卡片式完整信息，简略模式按行情列表形式展示直播状态点、主播名、在线人数、舰队人数和直播时长。
- 详细模式和简略模式中的在线、时长、舰队指标采用稳定列宽对齐；直播时长展示为 `HH:MM:SS`，未开播、未知或缺少开播时间时显示 `00:00:00`。
- “排序”组提供排序字段与排序方向控制；排序只影响当前 Webview 展示顺序，不修改 `bwatch.rooms` 配置。
- 排序字段支持默认顺序、是否开播、在线人数、舰队人数、粉丝人数和直播时长；方向支持大到小和小到大。
- 筛选支持全部、开播和未开播；未开播筛选包含未开播和未知/失败状态。
- 排序与筛选结果同时作用于详细模式、简略模式和当前展开的走势图。
- “分组”组展示并支持拖拽排序、重命名、上移、下移和删除自定义分组；每行左侧相邻显示分组名称与房间数，所有操作集中在右侧。拖拽手柄可把分组直接移动到任意目标位置并显示插入位置标记，上下按钮作为键盘操作和拖拽备用入口；排序按 `bwatch.groups` 数组顺序持久化。重命名通过预填当前名称的 VSCode 原生输入框完成，只修改名称并保留稳定 `id`、成员和顺序。新建分组由“直播间列表”子面板标题栏的功能图标触发 VSCode 原生输入框完成，不属于折叠配置区。分组名称不能为空、最多 24 个字符且不能与其他自定义分组重名。
- 每个主播条目提供“弹”按钮和分组归属入口；“弹”按钮把目标房间交给现有单房间弹幕会话，聚焦 `bwatch.danmaku` View 并自动开始连接，不创建并行弹幕连接。用户可把同一房间加入一个或多个自定义分组；第一版不提供拖拽房间排序，自定义分组自身支持拖拽排序和上下移动按钮。
- 主列表在详细模式和简略模式下均按分组展示：固定 `全部` 分组永远位于首位并展示当前排序筛选后的全部监控房间，后续每个自定义分组按持久化顺序展示当前排序筛选结果与该分组成员的交集；总览和历史走势图中的自定义分组筛选项使用相同顺序。
- 固定 `全部` 和每个自定义分组的表头显示该组当前实际展示主播的在线人数合计、舰队总人数合计和 `开播人数/总人数`；开播人数只统计 `status === 'live'` 的主播，在线人数或舰队字段不可用的单个主播按 `0` 贡献参与合计。详细模式和简略模式下，两个合计数字分别与主播条目的在线人数列、舰队人数列对齐，人数比例位于最右列，折叠后仍保留显示。
- 主列表分组支持折叠和展开；折叠状态属于 Webview UI 状态，不修改 VSCode 配置；分组箭头使用固定尺寸图标槽位并与标题垂直居中，不依赖系统字体中的箭头字符。
- 直播间列表整体展开状态、控制面板展开状态、展示模式、排序字段、排序方向、状态筛选、主列表分组折叠状态、房间分组编辑区展开状态、单主播走势展开状态、单主播走势时间宽度、总览/历史合计开关、总览走势展开状态、总览走势时间宽度、总览/历史图表高度、总览候选范围和总览图例隐藏房间集合通过 Webview 状态保存；切换到其他 VSCode 面板再返回时不应重置。
- “刷新”组提供自动刷新开关、总轮询间隔、房间状态/在线人数/粉丝数/舰队人数四类数据请求间隔输入和开播提醒开关；所有间隔最小值为 15 秒，开播提醒开关状态同步到 `bwatch.notifications.liveStart.enabled`。
- 常驻的主列表控制区提供“小图”按钮；开启后每个主播条目下展开一条在线人数迷你走势图。主播总览和历史走势各自拥有常驻标题栏与展开/收起按钮，收起时只隐藏具体内容，标题栏继续显示。
- 主列表控制区提供小图统一横轴时间宽度滑杆，最小 1 分钟、最大 6 小时、默认最近 1 分钟；所有单主播小图均展示从“当前最新刷新时间减去所选宽度”到当前最新刷新时间的在线人数走势。
- 时间宽度滑杆拖动过程中只实时更新滑杆值和“最近 N 分钟/小时”标签，松开或提交后再重绘走势图，避免拖动中的 range 控件被 Webview 重新渲染替换导致拖拽中断。
- 每个主播的走势图始终按自身当前窗口内的有效在线人数 min/max 独立缩放，不提供统一纵轴切换。
- 单主播迷你走势图和总览大图的横轴宽度应随 VSCode 侧栏横向空间变化自动调整；Webview 按当前图表容器像素宽度重新计算 SVG viewBox、坐标轴和折线路径，不通过横向缩放整张 SVG 适配宽度。
- 走势图宽度变化只改变相同时间范围内的横向点位密度；折线粗细、坐标文字和数字不应随侧栏宽度变化产生形变。当可用宽度低于最小可读宽度时，图表区域保留最小宽度并允许局部横向滚动。
- 聚合走势图的横轴和纵轴根据当前实际绘图区宽高动态生成刻度和对应网格线：横轴优先使用整分钟的 `1/2/5/10/15/30` 分钟及整小时步长，纵轴使用 `1/2/5 × 10^n` 的易读整数步长。宽度或高度增加时可展示更多刻度，空间不足时按最小像素间距自动裁剪内部刻度，始终保留起止时间和纵轴范围端点。
- 点击“主播总览”面板标题栏的展开按钮后，在汇总信息与主播列表之间展示主播总览大图；标题栏始终显示，收起时只隐藏面板内容。
- 总览大图默认纳入当前监控列表中的全部关注直播间，不受列表“全部/开播/未开播”筛选影响；每个主播用不同颜色在同一张 SVG 中叠加展示在线人数走势。
- 总览大图提供可多选的候选范围按钮：`全部` 包含所有关注直播间，`开播` 包含当前正在开播的直播间，`有数据` 包含当前总览时间窗口内存在大于 `0` 的有效在线人数采样点的直播间；每个自定义分组也作为一个候选范围。每个范围按钮文字后显示 `当前开播人数/该范围实际总人数`。图表展示所有已选范围内主播的并集，同一房间按房间号去重并保持监控列表顺序；`0` 和 `null` 采样不算“有数据”筛选结果。默认选择 `全部`，允许取消至零个范围。
- 总览大图的每个候选范围都提供独立 `Σ` 按钮；当前主筛选为任意范围时，均可同时添加全部、开播、有数据及多个自定义分组的合计曲线。每条合计只对自身候选范围内全部主播的同一采样时刻在线人数求和，并以范围名称、`当前开播人数/范围实际总人数`、独立 ID、稳定颜色和虚线样式加入图表、统一纵轴、图例及悬浮读数。合计口径不随单个主播图例的隐藏状态改变，合计图例本身可单独隐藏或恢复。
- 总览大图拥有独立横轴时间宽度滑杆，最小 1 分钟、最大 6 小时、默认最近 1 分钟；该滑杆不影响每个主播条目下的迷你走势图时间窗口。
- 总览大图的独立时间宽度滑杆同样在拖动过程中只更新标签，松开或提交后再重绘总览图，保证滑块可连续拖动。
- 总览大图和历史走势图各自提供独立的图表高度滑杆，可在 `160px` 到 `640px` 之间调整，默认 `240px`；拖动时预览数值，松开后按新高度重新计算坐标轴、网格、折线和悬浮定位。两者高度分别保存在 Webview UI 状态中，互不影响。
- 总览大图下方展示颜色图例；图例顶部提供“隐藏全部”和“全部显示”批量操作，分别作用于当前图表的全部曲线；每个图例项在主播名或合计名称后显示当前图表时间范围内最后一个有效采样点的在线人数，没有有效采样时显示 `--`；图例按该在线人数从大到小稳定排序，数值相同保持原序，`--` 项排在最后；图例项可点击隐藏或恢复对应曲线，隐藏状态不影响监控列表、历史缓存和刷新，图例名称与数字用删除线表示隐藏。主播范围多选、图例隐藏集合和合计范围集合分别持久化且相互独立，点击范围标签不清空另外两类状态。
- 图例在线人数排序只作用于图例 DOM 渲染顺序，不改变传入 SVG 的曲线数组、折线绘制层级或颜色映射；图例与 SVG 绘制路径需分别保持可执行，避免任一聚合图异常中断主列表和单主播小图重绘。
- 鼠标悬浮在大图区域时，按横向位置换算时间点，并在浮层中展示当前可见主播在该时间附近最近有效采样点的在线人数。
- 开启“历史”后，在汇总信息与主播列表之间展示本地历史查询面板；该面板不触发 B站接口刷新，只读取 `OnlineHistoryStore` 中已持久化的本地历史。
- 点击“历史走势”面板标题栏的展开按钮后展示历史查询内容；标题栏始终显示，收起时只隐藏面板内容。历史面板提供日历输入和有数据日期快捷按钮；只有 `OnlineHistoryStore.getAvailableDates()` 返回的日期可被选中，默认选择最近一个有数据日期。历史面板展开期间，每次完成快照刷新时按本地时区检查自然日边界；跨日后的首个采样完成后自动重新加载有数据日期列表，同一自然日内不重复扫描历史文件。日期列表更新时保留仍然有效的当前选择和当日时间范围，不自动跳转到最新日期。
- 历史面板提供当日双端范围条，范围固定为所选日期本地自然日的 `00:00` 到 `23:59`；拖动两端手柄时即时更新当前范围标签，松开或提交后再按包含结束整分钟的时间范围查询本地历史。
- 总览与历史走势图使用一致的纵向控制布局：标题、筛选范围、日期/时间范围各自占用独立行，时间范围条横跨面板可用宽度；历史日期输入和有数据日期快捷按钮位于同一日期控制区并可响应式换行。历史走势图复用总览图的 SVG 坐标轴、颜色、图例最新有效在线人数、在线人数降序排序、图例隐藏/恢复、悬浮读数浮层和像素级自适应宽度行为；图表和图例不得以内容最小宽度撑大面板，窗口变宽时只增加横轴像素宽度和采样显示密度，低于最小图宽时才允许横向滚动。历史图例数字表示所选时间段内该曲线最后一个有效采样点。
- 历史走势图提供可多选的 `全部`、`有数据` 和每个自定义分组范围，不提供当前直播状态或是否开播范围；每个范围按钮文字后显示 `当前开播人数/所选历史时间段内该范围实际总人数`。图表展示已选范围内主播的去重并集，`有数据` 要求所选时间段内存在大于 `0` 的有效在线人数采样，只有 `0` 或 `null` 的直播间不纳入该范围；每个范围均有独立 `Σ` 按钮，可同时添加多个范围合计曲线，范围选择、合计选择和图例隐藏状态相互独立。
- VSCode 命令面板提供 `BWatch: Refresh Live Rooms`、`BWatch: Add Live Room`、`BWatch: Remove Live Room`、`BWatch: Open Live Room`、`BWatch: Diagnose Network`。
- `BWatch: Diagnose Network` 会测试房间基础信息、在线人数、舰队人数、粉丝数和主播搜索接口，并把代理模式、代理来源、auto 本地代理候选、HTTP 状态、B站错误码和错误详情写入 `BWatch` 输出面板。

## 配置契约

| 配置项 | 类型 | 默认值 | 行为 |
|---|---|---:|---|
| `bwatch.rooms` | `string[]` | `[]` | 监控的 B站直播间房间号列表；无效和重复项会被忽略。 |
| `bwatch.groups` | `{ id: string; name: string; rooms: string[] }[]` | `[]` | 自定义分组列表；无效分组、重复分组和非当前监控房间成员会被忽略或过滤。 |
| `bwatch.autoRefresh.enabled` | `boolean` | `true` | 是否启用自动刷新。 |
| `bwatch.autoRefresh.intervalSeconds` | `number` | `15` | 自动刷新间隔；低于 15 时按 15 秒执行。 |
| `bwatch.dataRefresh.baseInfoIntervalSeconds` | `number` | `15` | 房间基础状态和元数据请求间隔；低于 15 时按 15 秒执行。 |
| `bwatch.dataRefresh.onlineIntervalSeconds` | `number` | `15` | 在线人数请求间隔；低于 15 时按 15 秒执行。 |
| `bwatch.dataRefresh.fansIntervalSeconds` | `number` | `300` | 粉丝数请求间隔；低于 15 时按 15 秒执行。 |
| `bwatch.dataRefresh.guardIntervalSeconds` | `number` | `60` | 舰队人数请求间隔；低于 15 时按 15 秒执行。 |
| `bwatch.notifications.liveStart.enabled` | `boolean` | `true` | 是否启用开播提醒。 |
| `bwatch.network.proxy.mode` | `'auto' \| 'manual' \| 'off'` | `'auto'` | B站接口请求代理模式；`auto` 先读 VSCode `http.proxy`，再读 `HTTPS_PROXY`/`HTTP_PROXY`，链路失败时继续探测 `127.0.0.1:7897`、`127.0.0.1:7890` 和 `127.0.0.1:10809`；`manual` 使用 BWatch 手动代理 URL；`off` 强制直连。 |
| `bwatch.network.proxy.url` | `string` | `''` | `manual` 模式下使用的 HTTP/HTTPS 代理地址，例如 `http://127.0.0.1:7890`；不支持 SOCKS 代理。 |

## 数据与状态

- 内部直播间状态使用 `LiveRoomStatus` 表示，包含房间号、短号、标题、主播名、粉丝数、封面、直播状态、在线观众人数、人气、舰队总人数、开播时间、已开播时长、最后更新时间和错误信息；当前 UI 不展示单房间更新时间和人气。
- `LiveRoomStatus.fansCountStale`、`guardFleetStale` 和对应的 `LastSuccessAt` 字段表示补充字段是否因本轮失败而沿用缓存；该状态只用于当前 Webview 展示，不改变历史在线人数数据。
- 添加候选结果使用 `RoomSearchResult` 表示，包含房间号、标题、副标题、详情、是否开播、是否已监控、来源和头像；`monitored` 由扩展宿主按当前 `bwatch.rooms` 配置计算，并展示在 VSCode 原生候选列表中。
- 自定义分组使用 `RoomGroup` 表示，包含稳定 `id`、展示名称 `name` 和成员房间号 `rooms`；分组只引用当前监控房间，删除房间时会从分组成员中移除该房间。
- 在线人数历史使用 `OnlineViewerHistoryPoint = [timestampMs, online]` 表示，`online` 可为 `number` 或 `null`；`OnlineHistoryStore` 在 VSCode 扩展本地存储目录中按房间长期保存历史文件，文件同时保存该房间最近已知主播名。
- `MonitorSnapshot.onlineHistory` 只按当前监控房间号传递最近 24 小时内的绘图数据，当前走势图可读取最近 1 分钟到 6 小时窗口，避免 Webview 一次加载长期历史。
- 删除房间或配置移除房间只从当前监控列表和快照中过滤该房间，不删除该房间长期历史；重新添加同一房间后，近期快照可重新读取该房间已有历史。
- 旧版本写入 VSCode `globalState` 的 `bwatch.onlineHistory.v1` 历史会在 `OnlineHistoryStore` 初始化时迁移进本地历史文件；旧版本地历史数组文件也会兼容读取，后续采样优先写入包含主播名元数据的新格式本地文件。
- 历史查询通过 `OnlineHistoryStore.getAvailableDates()` 获取有本地数据的日期列表，通过 `OnlineHistoryStore.queryDateHistory(date, startMinute, endMinute)` 读取某个本地自然日内指定分钟范围的数据；历史查询结果不写入 `MonitorSnapshot`。
- 历史查询结果中的 `HistoryRoomSeries.anchorName` 按当前监控快照已知主播名、本地历史文件保存的最近已知主播名、房间号的顺序兜底；接口失败返回的 `-`、空字符串或 `房间 {roomId}` 不会覆盖已保存的有效主播名。
- Webview 接收历史查询结果后会再次进行容错归一化：忽略无效房间、非法时间戳和非法在线人数，按时间戳去重排序，并修正异常起止时间；单条历史缓存记录异常时只影响该记录，不会使整个历史走势图进入渲染失败状态。渲染异常仍保留固定高度的可读错误占位，并显示可诊断的错误信息。
- 每次刷新完成后按房间追加一个采样点；未开播房间在线人数记录为 `0`，直播中在线人数接口失败或不可用时记录为 `null`。
- 每条合计曲线按时间戳对其自身筛选范围内主播求和；成员在该时间戳没有采样时按 `0` 参与求和，使后来加入分组的主播不会抹掉此前已有的合计历史；成员存在明确 `null` 失败采样时该时间点合计记为 `null` 并断线；如果该时间点没有任何有效数值，也记为 `null`。多条合计可同时存在，且总览图与历史图分别持久化各自的已选合计范围集合。
- 走势图用 Webview 内 SVG 绘制，不引入图表库；`null` 采样点保留但不参与 min/max 缩放，并在折线中表现为断线；SVG 宽度基于容器宽度动态重绘，避免 CSS 非等比拉伸造成线条和文字变形。
- 单主播迷你走势图和总览大图的坐标轴、纵轴最大/最小值、横轴起止时间应绘制在同一个 SVG 图表坐标区内，不使用脱离图表的外置浮动标签。
- 总览大图按当前候选范围内可见主播的有效在线人数采样计算统一纵轴，非负在线人数从 `0` 起并保留实际最大值，内部刻度使用自适应易读步长，便于在同一坐标系中比较绝对在线人数；数据不足以形成折线时显示“数据积累中”，全部主播被图例隐藏时显示“已隐藏全部主播”并保留图例用于恢复。
- 直播状态分为 `live`、`offline`、`unknown`。
- 已开播时长由接口返回的开播时间计算；UI 中以 `HH:MM:SS` 展示，未开播显示 `00:00:00`。
- 直播间状态数据仍按配置的自动刷新间隔或手动刷新从接口获取；直播中且存在开播时间时，Webview 基于 `liveStartTime` 在本地每秒更新时长显示，不等待下一轮接口刷新。
- 列表顶部汇总展示本轮统一刷新时间和整体刷新状态；整体状态分为更新中、未刷新、刷新成功、部分失败和刷新失败。
- 每个房间左侧状态点表示是否直播中：绿色为直播中，红色为不在直播或状态未知。
- 列表顶部展示当前筛选后可见主播数量。
- 网络失败、接口错误、房间不存在或字段缺失时，房间显示 `unknown`、红色直播状态点或错误信息，顶部整体刷新状态体现失败范围。
- 底层 `fetch failed`、`EACCES 198.18.x`、TLS/证书握手失败、域名解析失败和 HTTP 非 200 会被格式化为更可读的错误信息；`198.18.x` 连接拒绝按代理/fake-ip 链路异常提示。

## 刷新配置与请求节奏

- 列表总轮询仍由 `bwatch.autoRefresh.intervalSeconds` 控制，负责快照刷新和 UI 更新；数据实际请求由以下四个独立间隔控制：`bwatch.dataRefresh.baseInfoIntervalSeconds`（房间状态/名称/标题，默认 15 秒）、`bwatch.dataRefresh.onlineIntervalSeconds`（在线人数，默认 15 秒）、`bwatch.dataRefresh.fansIntervalSeconds`（粉丝数，默认 300 秒）和 `bwatch.dataRefresh.guardIntervalSeconds`（舰队人数，默认 60 秒）。所有间隔最小为 15 秒。
- 基础信息使用一次批量请求；在线人数、粉丝数和舰队人数仍按房间补充请求，补充请求最多 6 个房间并发。每类字段只有到达自己的刷新间隔才发起请求，未到期时复用成功缓存。
- 在线人数缓存按房间和主播 UID 保存。在线接口到期刷新失败时沿用上次成功值，并通过 `onlineStale` 与最近成功时间传递给 UI，数字显示为黄色并提供悬浮说明；未到期复用不标记为失败。没有成功缓存时在线人数保持 `null`，不会回退到基础信息中的人气值。
- 配置项从侧栏“刷新”模块修改后写入 VSCode 设置，配置变化会重建轮询并触发一次刷新；“分组”管理模块位于刷新模块之后。

## 控件视觉规范

- 所有选择或切换型按钮统一使用两种状态：未选中/关闭为透明背景加边框，选中/开启为实心 VSCode 按钮色并使用按钮前景色。
- 该规则应用于展示模式、主播状态筛选、小图开关、总览/历史筛选、聚合曲线开关、历史日期选择以及可展开面板的激活状态；普通操作按钮仍保持命令按钮样式。
- 刷新区的数字输入框统一使用可容纳三位数和数字微调控件的宽度，避免 `300` 等配置值被截断。
- 单主播小图在成功绘制、数据积累中和无有效数据时保持相同图表高度；总览和历史聚合图在成功绘制、读取中、空数据和错误提示时保持各自当前设定的聚合图高度，避免滑动时间范围或刷新时页面跳动。

## 开播提醒规则

- 只有当 `bwatch.notifications.liveStart.enabled` 为 `true` 时才显示通知。
- 状态从非直播中变为直播中时触发一次通知。
- 通知正文优先显示主播名，并附带直播标题；主播名缺失时回退显示房间号。
- 房间持续直播时后续刷新不重复通知。
- 接口失败产生的 `unknown` 状态不会覆盖已知直播状态，避免错误状态导致下一轮误报。

## 外部服务边界

- 扩展通过 B站直播房间基础信息接口 `xlive/web-room/v1/index/getRoomBaseInfo` 获取状态和人气。

## 历史跨日查询

- 历史走势日期选择最多保留两个日期；两个日期必须都来自本地历史日期列表且为相邻自然日。日期输入框用于切换单日，日期按钮用于将相邻日期加入或从双日选择中移除；非相邻日期会切换为新的单日。
- 单日查询使用相对分钟 `0` 到 `1439`；双日查询使用相对第一天 00:00 的连续分钟 `0` 到 `2879`。扩展宿主一次查询整个日期范围，不在 Webview 侧拼接两次结果。
- `HistoryQueryResult` 返回 `dates`、`startMs`、`endMs` 和双日可选的 `boundaryMs`。`boundaryMs` 是第二天本地 00:00；双日图表横轴和悬浮时间显示 `MM/DD HH:mm`，并在该边界绘制独立午夜分界线。
- 切换单日/双日时保留已有起点；从单日扩展为双日默认把终点扩展到第二天 23:59，从双日退回单日时将终点裁剪到当天 23:59。历史存储仍按房间长期保存，不因日期范围查询改变。

## 走势图颜色

- 总览和历史走势图共用至少 24 种高区分度颜色。房间曲线按监控列表中的稳定房间索引取色，因此改变筛选范围不会导致同一主播换色；合计曲线从房间曲线索引之后取色，避免与同图房间曲线撞色。
- 当曲线数量超过预设调色板时，使用由曲线索引确定的 HSL 颜色作为兜底，不循环复用已有颜色；图例、折线、交互点和悬浮提示复用同一个颜色值。
- 直播中房间只通过 `xlive/general-interface/v1/rank/getOnlineGoldRank` 获取直播页同款在线观众人数 `onlineNum`；该接口失败时在线人数为 `null`，不回退使用基础接口 `online`。
- 扩展通过 `xlive/app-room/v2/guardTab/topList` 的 `info.num` 获取舰队总人数；不翻页统计舰长、提督和总督拆分。
- 扩展通过 `x/relation/stat?vmid={uid}` 的 `follower` 获取主播粉丝数；该请求失败时只显示粉丝数缺失，不影响房间状态刷新。
- 房间刷新不是所有字段都能批量获取：基础房间信息支持批量，粉丝数、舰队总人数和直播在线人数目前只能按房间/主播分别请求；客户端对这些补充请求做并发调度和短时缓存。
- 主播名搜索通过 `x/web-interface/search/type?search_type=live_user` 获取候选主播、房间号、头像、分区、粉丝数和开播状态；请求携带浏览器兼容请求头、搜索页 `referer` 和访客 cookie，以降低非浏览器请求触发 412 拦截的概率。
- 所有 B站接口请求通过统一网络适配层发起；代理模式为 `auto` 时优先复用 VSCode `http.proxy`，未配置时再使用环境变量 `HTTPS_PROXY`/`HTTP_PROXY`，链路失败时继续尝试常见 Clash/Mihomo 本地 HTTP 代理端口；代理模式为 `manual` 时使用 `bwatch.network.proxy.url`，代理模式为 `off` 时直连。
- 网络适配层不依赖额外运行时 npm 包，确保 `.vscodeignore` 排除 `node_modules` 后打包出的 VSIX 仍可正常激活；系统存在 `curl` 时可作为 HTTP/HTTPS 代理请求兜底。
- 当前代理支持范围仅限 HTTP/HTTPS 代理；使用 SOCKS 代理的用户需要改用代理客户端提供的 HTTP 或 mixed 端口。
- 批量查询参数使用 `req_biz=web_room_componet` 和重复的 `room_ids` 查询参数。
- 本项目不控制该接口的稳定性、限流、字段兼容性或响应时间。
- 接口异常必须被视为可恢复状态，不应导致扩展宿主或 Webview 崩溃。

## 单主播直播场次历史分析

### 入口与状态

- 历史走势控制面板顶部提供“主播 / 直播场次”二级级联下拉框。第一级切换主播，第二级读取并展示该主播全部本地长期历史场次；加载中、读取失败、无场次均在第二级控件中表达，不新增独立子面板。
- 分析主播房间号和选中场次通过 Webview getState/setState 保存；切换 VSCode 面板或收到快照重渲染时恢复选择。房间从当前监控列表删除时清除当前筛选，但不删除该房间长期历史。

### 场次识别

- 数据源为该房间全部本地长期在线人数历史，不新增 B站接口。
- 在线人数大于 0 的连续采样区间视为一场直播；在线人数为 0 结束当前场次；null 表示失败或断线，不强制切断场次，并计入总采样数但不计入有效采样数。
- 场次摘要包含 roomId、startMs、endMs、durationMs、peakOnline、sampleCount 和 validSampleCount，按结束时间从新到旧返回。没有采样、只有 0 或只有 null 时返回空列表。

### 历史走势联动

- 点击场次自动设置开始前 5 分钟到结束后 5 分钟的历史范围；跨午夜时使用现有相邻双日查询，范围最多保留两个自然日，并显示日期和时间边界。
- 快速定位只修改日期和起止时间，并将其他主播曲线默认标记为隐藏；用户仍可继续手动调整时间、范围筛选、图例隐藏和合计曲线。场次分析不替换历史范围候选主播，也不清空合计曲线；清除筛选后恢复选择前的图例隐藏状态。
