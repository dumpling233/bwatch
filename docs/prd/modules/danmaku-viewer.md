# 实时弹幕机

## 当前行为

`bwatch` 在 Activity Bar 的 `BWatch` 容器中提供独立 Webview View `bwatch.danmaku`。用户可以从当前监控房间列表选择直播间，也可以直接输入其他纯数字房间号，连接后实时查看该直播间的文本弹幕与 Super Chat（SC）。

## 用户交互

- 监控房间下拉列表显示主播名、房间号和当前开播状态：绿色圆点表示直播中，红色圆点表示未开播或状态未知；开播房间稳定排列在未开播房间之前，同状态房间保持监控列表原顺序。列表由直播监控快照同步，但弹幕机也允许直接输入未加入监控列表的房间号。
- 直播监控列表的详细模式和简略模式均提供“弹”按钮。点击后聚焦弹幕机 View、选中对应监控房间、切换到普通弹幕标签并调用现有单房间会话自动连接；如果已有其他房间连接，沿用切换房间时关闭旧会话和清空旧消息的规则。
- 用户主动点击“连接”后才建立弹幕长连接；同一时刻只维护一个直播间会话，切换房间会断开旧会话、取消仍在进行的 HTTP 初始化或 WebSocket 握手、清空旧弹幕并连接新房间。每次连接尝试只等待一条“服务器 + 代理”线路，失败后按短退避切换下一条，避免一次重连串行等待全部候选；同一代理候选内优先轮换 B站服务器。连接层分别检测传输健康与业务流健康：每 10 秒发送 WebSocket Ping，但单独缺少 Pong 不触发断线；只有连续 45 秒没有收到任何 WebSocket 业务帧或 Pong 才终止假活连接。即使 Pong 与应用心跳正常，连续两条普通弹幕的原始发送时间距本地收包时间超过 8 秒，或同一帧内弹幕发送时间跨度超过 5 秒，也将当前线路判定为业务退化并自动轮换。当前连接曾收到普通弹幕后，如果连续 3 个 10 秒窗口仍收到业务包、普通弹幕始终为 0 且累计至少 12 条其他业务命令，也会在距最后弹幕至少 30 秒后判定当前节点选择性停止文本弹幕并轮换线路；低于任一阈值的自然静默不触发该规则。
- 弹幕 View 内状态栏显示未连接、连接中、已连接、重连中或错误状态；连接成功后显示真实房间号和心跳返回的人气值。
- 连接状态下方显示当前监控房间的紧凑信息栏，包含主播名、直播标题、开播状态、在线人数、`HH:MM:SS` 开播时长、舰队总人数和粉丝数。信息直接复用直播监控模块同步的房间快照，不新增轮询或 B站接口请求；监控快照刷新后立即更新，直播中的开播时长由 Webview 每秒本地走秒。在线、舰队或粉丝字段沿用缓存时以黄色标记并在悬浮提示中显示最近成功时间，缺失值显示 `-`；直接输入的非监控房间明确显示未加入监控列表，不伪造指标。
- 工具栏提供“弹幕”和“SC”两个标签页并分别显示条数；当前标签通过 Webview 状态保存。SC 列表展示接收时间、SC 标记、金额、持续时间、发送者、UID、粉丝牌、房管标记和正文，其中通用元数据及 Emoji 显示选项与普通弹幕共用。
- 弹幕列表支持显示接收时间、发送者名称、发送者 UID、粉丝牌、房管标记、文本内容和弹幕颜色条；兼容经典 `DANMU_MSG` 用户元组和新版嵌套用户字段。
- “显示”控制面板可分别开启或隐藏接收时间、发送者名称、发送者 UID、粉丝牌、房管标记、弹幕颜色条和 Unicode Emoji 表情；文本内容始终显示。UID 和房管标记默认隐藏，其余信息默认保持原展示效果；选项变化立即作用于已有弹幕。
- 关闭“Emoji 表情”后，Unicode Emoji 不会被删除，而是在原位置转换为可读的方括号文本：已配置名称的表情显示中文名称，例如 `👍` 显示为 `[点赞]`；未配置名称的表情显示 Unicode 码位，例如 `🪿` 显示为 `[Emoji U+1FABF]`。该规则按完整序列识别 ZWJ 组合、肤色、旗帜和键帽，纯 Emoji 弹幕仍会显示；`[doge]` 等普通文字形式的表情代码保持不变。重新开启后从内存中的原始消息恢复 Emoji 图形。
- 每条弹幕左侧颜色条表示发送者在 B站选择的弹幕文字颜色，不表示用户等级、粉丝牌等级、房管身份或连接状态。
- 普通弹幕与 SC 只保存在扩展宿主与 Webview 内存中，分别最多保留最近 500 条和 100 条，不写入 VSCode 设置、扩展本地存储或日志文件。SC 按 B站消息 ID 去重；收到 `SUPER_CHAT_MESSAGE_DELETE` 后从内存列表移除对应 SC。
- 用户可以断开连接、清空当前列表、开启/关闭自动滚动，并从状态栏打开当前 B站直播间页面；自动滚动、显示控制面板展开状态和各信息显示选项通过 Webview 状态保存。“Emoji 表情”选项还会同步给扩展宿主的底部状态栏。
- 用户开始连接弹幕后，VSCode 窗口底部状态栏会显示连接/等待状态，并在每条新弹幕到达时实时替换为最新内容。正文压缩连续空白并最多显示 48 个 Unicode 字符，完整内容、房间、发送者和接收时间通过悬浮提示展示；关闭 Emoji 后，底部状态栏同步把 Emoji 原位转换为与列表一致的可读文本，纯 Emoji 弹幕也会作为最新消息显示。
- 主动断开时底部状态栏保留最后一条弹幕并切换为断开图标；清屏会清除最新内容并按当前连接状态显示等待提示或隐藏；扩展未使用弹幕连接且没有最新消息时不占用底部状态栏。状态栏项使用稳定 ID `bwatch.latestDanmaku`，可通过 VSCode 状态栏上下文菜单隐藏。
- 用户可以运行命令 `bwatch.toggleDanmakuStatusBar` 或使用默认快捷键切换底部最新弹幕状态栏：Windows/Linux 为 `Ctrl+Alt+D`，macOS 为 `Cmd+Alt+D`。开关默认开启，选择通过扩展 `globalState` 的 `bwatch.danmakuStatusBar.enabled` 保存并在窗口重载后恢复。关闭只隐藏状态栏项，不断开弹幕长连接、不清空消息，也不停止会话订阅；关闭期间收到的新弹幕仍进入原有内存队列，重新开启时立即按当前快照显示最新内容。
- Webview 隐藏后使用 `retainContextWhenHidden` 保持当前界面和会话；扩展停用时关闭连接并释放心跳、认证和重连定时器。

## 实时弹幕获取链路

1. 使用 `room/v1/Room/get_info` 把短房间号或普通房间号解析为真实房间号。
2. 匿名请求 `x/web-interface/nav` 获取当前 WBI 图片密钥，按 B站 WBI 混排规则生成签名密钥并缓存约 12 小时。
3. 对 `xlive/web-room/v1/index/getDanmuInfo` 的 `id`、`type` 和 `wts` 参数生成 `w_rid`；接口返回 `-352` 时强制刷新 WBI 密钥并重试一次。
4. 从接口响应获取连接 `token` 和弹幕服务器 `host_list`，展开为 `代理候选 × 服务器` 的有序线路集合并维护轮换游标，连接 `wss://{host}:{wss_port}/sub`。每次尝试在握手前先推进游标且只等待一条线路；线路异常关闭或业务流退化后先短退避，再从下一服务器继续，完整轮换当前代理下的服务器后才降级到下一代理候选。切房或断开通过会话级 `AbortController` 同时取消 HTTP 初始化和 WebSocket 握手；连接尝试世代号和 socket 身份校验会忽略旧连接迟到的消息、错误与关闭事件。
5. WebSocket 打开后发送匿名认证包；认证成功后立即发送一次心跳，此后每 30 秒发送心跳。
6. 按 16 字节大端包头拆分消息；协议版本 `2` 使用 zlib 解压，版本 `3` 使用 Brotli 解压，并递归拆分压缩体内的完整子包。结构层返回“已解出的包 + 局部错误”，单个压缩包解压失败只丢弃该包，损坏长度会尝试重新同步到后续合法包头；完成结构解包后逐个业务命令独立解析，单个损坏或未知 JSON 命令只跳过自身，不丢弃同一帧前后正常命令。
7. 把命令前缀为 `DANMU_MSG` 的文本弹幕标准化后推送到普通弹幕列表；把 `SUPER_CHAT_MESSAGE` 与 `SUPER_CHAT_MESSAGE_JPN` 标准化后推送到独立 SC 列表，并处理 `SUPER_CHAT_MESSAGE_DELETE` 删除事件。扩展宿主把同一收包任务内的普通弹幕合并为一次微任务消息，Webview 使用 `DocumentFragment` 一次提交该批 DOM，并只更新一次计数和滚动位置。其他礼物、上舰、进场和互动命令暂不展示。
8. 30 秒应用心跳保留用于 B站人气与会话维持；额外的 10 秒 WebSocket Ping 只用于探测和测量 RTT。传输健康依据最后一个任意业务帧或 Pong 的绝对时间判断；部分 B站节点、透明代理或 TUN 链路可能不返回 Pong，只要应用心跳或其他业务帧仍在 45 秒窗口内到达，就保持当前连接。普通弹幕保留 B站发送时间 `sentAt` 和本地收包时间 `receivedAt`，用于识别“传输仍响应但业务消息被节点或代理缓存”的退化线路。业务流还按诊断窗口累计“其他命令持续到达但普通弹幕为 0”的选择性饥饿证据；该检测要求当前连接已有普通弹幕基线、连续 3 个窗口、至少 30 秒无普通弹幕和累计 12 条其他命令，任一窗口收到普通弹幕、没有业务包或没有其他命令都会清零证据。达到阈值后终止当前连接并切换下一线路，随后按 1、2、5、10 秒上限递增重连；选择性饥饿轮换至少冷却 60 秒，认证成功不立即清零重连计数，连接稳定 60 秒或连续收到 5 条低延迟弹幕后才恢复健康计数。认证失败会强制刷新服务器配置和 token；普通失败在至少 3 次且完成当前有序线路集合的一轮尝试后刷新配置。首次 HTTP 初始化的临时网络错误进入同一重试状态机，明确的无效房间号错误才停止自动重试。
9. 传输探针记录连续未收到 Pong 的次数、最后一次应用心跳发送/响应、最后业务帧、普通弹幕、当前静默时长和 Ping RTT；如果定时器漂移超过 5 秒，则记录 Extension Host 事件循环延迟、跳过本轮网络超时判断，并在随后 20 秒内避免把宿主阻塞造成的消息时间滞后或选择性饥饿误判为线路退化。连接期间每 10 秒向 `BWatch` 输出一条聚合流量窗口，包含原始帧/字节/解包数量、业务包、弹幕、SC、其他命令、解码/命令错误、无正文的命令类型分布、发送时间跨度和收包延迟范围；选择性饥饿观察额外记录连续窗口数、其他命令累计数、距最后弹幕时间、冷却状态和当前线路。Webview 同周期输出接收批次、消息数、宿主到 Webview 最大交付延迟、最大 DOM 提交耗时、定时器漂移和当前列表数量；批次投递失败单独记录。所有诊断均不记录弹幕正文、发送者或 UID。
10. 首次打开 Webview 时发送包含内存消息的完整快照；后续连接状态和心跳更新只发送状态、人气及错误字段，不重复传输或重建最近 500 条弹幕和 100 条 SC。

## 网络与权限边界

- 不要求 B站登录，不读取用户 Cookie、账号或密钥，不支持发送弹幕。
- HTTP 初始化请求复用 BWatch 现有 `FetchLike` 网络适配层；WebSocket 在 `auto` 模式下尝试 VSCode/环境代理解析结果、直连和常见本地 HTTP 代理端口，在 `manual` 模式下使用用户指定 HTTP/HTTPS 代理，在 `off` 模式下只使用直连。
- WebSocket 代理使用 `https-proxy-agent`，只支持现有 BWatch 声明的 HTTP/HTTPS 代理边界，不支持 SOCKS。
- 网页端 WBI、`getDanmuInfo` 和直播弹幕协议均属于 B站非正式接口，可能随时调整字段、签名、压缩或认证规则。

## 当前范围

- 当前版本展示单直播间实时文本弹幕与实时 Super Chat；只接收连接建立之后的新消息，不额外请求正在展示或历史 SC 的 REST 数据。
- WebSocket 断开期间没有可靠的匿名历史弹幕补拉接口，因此线路轮换与重连用于缩短异常窗口，但不能承诺补回断线期间服务器未再次下发的消息。
- 暂不展示礼物、上舰、进场、关注、点赞或独立房管事件。
- 暂不提供关键词过滤、用户过滤、弹幕发送、弹幕持久化、导出或多房间并行聚合。
