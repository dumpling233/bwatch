# Agent 行为规则

本文件约束启用 `prd-keeper` 时 AI agent 的行为。

## 入口规则

- 每个新任务开始时读取 `SKILL.md` 和 `routing.yaml`。
- 同一会话里的后续任务也要重新读取路由，不依赖上一轮记忆。
- 维护 `AGENTS.md`、`CODEX.md` 与 `CLAUDE.md` 三个根入口文件。
- 入口文件只能做薄壳，不复制完整规则正文。

## 证据规则

- 非平凡变更前先读 PRD，再读相关代码。
- 如果相关 PRD 缺失、仍为 `待确认` 或与代码现状不一致，先补齐本次任务相关范围的 Baseline PRD，再继续修改代码。
- 修改 PRD 里的运行行为前，必须检查代码证据。
- 区分已由代码确认、用户明确说明、根据代码推断和未知的信息。
- 不确定的信息写为 `待确认`。
- 不根据项目名、默认 README 模板或文件名猜测产品行为。

## 修改规则

- 用户最新明确需求优先。
- 如果用户需求与旧 PRD 冲突，先满足用户需求，再更新 PRD。
- 修改范围应限制在受影响模块或流程内。
- 除非任务明确要求，否则不做大范围重构。
- 不编造模块、接口、权限、数据字段、配置项或第三方服务。

## 收尾规则

- 运行与变更匹配的验证。
- 行为变更后更新对应 PRD 或模块文档。
- 每次非平凡任务都记录到当前 Git 用户当天的 PRD 日志文件，文件名格式为 `YYYYMMDD-{git-user}.md`。
- 最终回复说明代码变更、PRD 更新、日志状态、验证结果和风险。
- 如果本次任务执行了 Baseline PRD 回填，最终回复说明回填范围、证据来源和仍待确认事项。
