# PRD 治理规则

本文件定义 PRD 系统的内容边界和更新条件。

## 文档边界

- `docs/prd/README.md` 是 PRD 总入口和导航页。
- `docs/prd/product-overview.md` 记录产品定位、核心场景、业务规则、边界和风险。
- `docs/prd/architecture.md` 记录架构分层、目录映射、数据流、权限、配置、环境变量和外部服务边界。
- `docs/prd/modules/README.md` 记录模块索引。
- `docs/prd/modules/*.md` 与 `docs/prd/modules/**/*.md` 记录具体模块的当前行为。
- `docs/prd/prd_log/YYYYMMDD-{git-user}.md` 按 Git 用户和日期记录历史变更和任务日志；`{git-user}` 必须读取 `git config user.name`，缺失时再回退到 `git config user.email` 或 `unknown`。

## 更新触发条件

- 相关 PRD 缺失、仍为 `待确认` 或与代码现状不一致时，先进行本次任务相关范围的 Baseline PRD 回填。
- 用户可见行为变化时更新 PRD。
- 页面布局、交互、文案、导航或入口变化时更新 PRD。
- API 入参、出参、错误或调用方式变化时更新 PRD。
- 数据结构、数据库字段、配置项或存储格式变化时更新 PRD。
- 权限、登录、账号、角色或鉴权流程变化时更新 PRD。
- 业务规则、状态流转、限制或边界条件变化时更新 PRD。
- 模块、命令、接口、任务或工作流新增/删除时更新 PRD。
- 缺陷修复导致实际行为与文档不一致时更新 PRD。

## 写作规则

- PRD 描述当前真实行为，不写愿望、计划或猜测。
- 历史过程写入日志，不写入模块当前行为文档。
- 每个非平凡任务追加到当前 Git 用户当天的日志文件，不追加到多人共享的日期日志文件。
- 不在 PRD 中复制大段实现代码。
- 需要时记录契约、字段、权限、错误、约束和边界。
- 无法确认归属或行为时写入 `待确认`。
- 不要求一次性消除所有 `待确认`；优先消除本次任务相关范围内影响判断和实现的 `待确认`。
- 如果 PRD 不更新，最终回复必须说明没有产品行为影响的原因。
