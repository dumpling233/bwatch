# 可复用坑点

维护本项目时发现的可复用问题记录在这里。

## 当前坑点

- 不要从项目名推断产品模块。
- 不要把默认 README 模板当作产品需求。
- 没有代码或用户明确要求时，不要编造 API 契约、数据结构、权限或外部服务。
- PRD 缺失或存在 `待确认` 时，不要直接跳过 PRD；先补齐本次任务相关范围的 Baseline PRD。
- 根入口文件必须保持薄壳。
- 当前行为写入 PRD 或模块文档。
- 历史决策写入独立 PRD 日志文件。
- B站弹幕节点、透明代理或 TUN 链路可能持续传输应用心跳和业务帧但不响应 WebSocket Pong；不得用单个 Ping 周期无 Pong 直接判定弹幕连接失效，应以覆盖 30 秒应用心跳周期的绝对入站静默窗口判活。
- WebSocket 帧、心跳或其他直播业务命令持续到达，只能证明传输层仍活跃，不能证明 `DANMU_MSG` 文本弹幕流健康；只有结合当前连接已有弹幕基线、连续多窗口无文本弹幕、足量其他业务命令、事件循环漂移排除和轮换冷却，才能保守判定节点选择性漏发并切换线路。
- PRD 路径变化时，同步更新 Skill、路由、入口、PRD 索引和日志规则。
- PRD 文档必须以中文为主要文本；路径、命令、文件名、变量名、函数名和专有工具名可以保留英文。

## 记录门槛

- 只有未来可能重复出现的问题才写入本文件。
- 记录必须抽象成脱离本次会话仍然成立的经验。
- 过期坑点要删除，不要让本文件变成流水账。
- 一次性任务过程写入 `docs/prd/prd_log/YYYYMMDD-{git-user}.md`。
